# 图书管理后台需求文档

## 1. 项目目标

建设一个仅供管理员使用的图书管理后台，并通过逐步实现业务模块，熟悉需求分析、数据建模、接口设计、Spring 分层、SQL、事务、安全、测试和前后端联调。

第一阶段不包含读者门户、完整 RBAC、文件上传、Redis、消息通知和线上部署。

## 2. 用户与核心流程

唯一角色为管理员 `ADMIN`，可以登录后台、维护分类与图书、维护读者、办理借阅和归还、查看统计数据。

核心流程：

1. 管理员使用用户名和密码登录，获得有效期两小时的 JWT。
2. 管理员维护分类、图书和读者基础数据。
3. 办理借阅时，系统检查读者状态、借阅上限和图书库存，成功后扣减可用库存。
4. 办理归还时，系统关闭借阅记录并恢复可用库存。
5. 系统根据借阅记录计算当前借出、逾期和热门图书。

## 3. 数据模型

### 管理员 `sys_user`

- 用户名唯一；密码必须以 BCrypt 哈希保存。
- `status=1` 才允许登录，当前只有 `ADMIN` 角色。

### 分类 `book_category`

- 分类名称唯一，支持排序、启停用和逻辑删除。
- 已被有效图书引用的分类不能删除。

### 图书 `book`

- ISBN 唯一，必须关联一个有效分类。
- `total_stock` 为总库存，`available_stock` 为可借库存，必须满足 `0 <= available_stock <= total_stock`。
- `status=1` 表示可用；使用 `version` 进行乐观锁控制，使用 `deleted` 逻辑删除。

### 读者 `reader`

- 读者编号 `reader_no` 唯一。
- `max_borrow_count` 必须大于零；停用读者不能借书。
- 存在未归还记录时不能删除。

### 借阅记录 `borrow_record`

- 状态为 `BORROWED`、`RETURNED` 或 `OVERDUE`。
- `borrowed_at < due_at`；归还后填写 `returned_at`。
- 历史记录不可物理删除。

## 4. 接口约定

所有业务接口以 `/api` 开头，除登录和 Swagger 外都要求：

```http
Authorization: Bearer <JWT>
```

成功响应：

```json
{ "code": 0, "message": "success", "data": {} }
```

分页数据：

```json
{
  "records": [],
  "total": 0,
  "page": 1,
  "size": 10
}
```

主要错误状态：400 参数错误、401 未登录、403 无权限、404 不存在、409 状态冲突、501 学习任务尚未实现。

已完成的接口：

- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/books`
- `GET /api/books/{id}`
- `GET /api/categories/options`

## 5. 学习任务与验收条件

### LEARNING-1：分类管理

实现 `GET/POST/PUT/DELETE /api/categories`。

- 分页支持名称和状态筛选。
- 新增、修改时名称不能为空且不能重复。
- 被有效图书引用时删除返回 409，否则逻辑删除。
- 补齐分类管理表格、表单和状态展示。

### LEARNING-2：图书管理

实现 `POST /api/books`、`PUT /api/books/{id}`、`DELETE /api/books/{id}`。

- ISBN、书名、作者、分类和总库存必填，ISBN 不能重复。
- 新增时 `available_stock=total_stock`。
- 修改总库存时不得小于已借数量，即 `total_stock - available_stock`。
- 存在未归还记录的图书不能删除；否则逻辑删除。
- 使用已有图书查询页补充新增、编辑和删除交互。

### LEARNING-3：读者管理

实现读者分页、详情、新增、修改、启停用和删除。

- 读者编号唯一，邮箱格式正确，借阅上限大于零。
- 停用后保留历史记录，但不能产生新借阅。
- 有未归还记录时删除返回 409。

### LEARNING-4：借阅

实现借阅记录分页和 `POST /api/borrows`。

- 在同一事务中检查读者存在且启用、当前借阅数未达上限、图书存在且启用、可用库存大于零。
- 插入 `BORROWED` 记录，并将 `available_stock` 减一。
- 任一检查或更新失败时必须整体回滚。

### LEARNING-5：归还

实现 `POST /api/borrows/{id}/return`。

- 只有 `BORROWED` 或 `OVERDUE` 记录允许归还。
- 在同一事务内设置 `returned_at`、状态改为 `RETURNED`，图书可用库存加一。
- 重复归还返回 409，且库存不能重复增加。

### LEARNING-6：统计看板

实现 `GET /api/dashboard/summary`，使用自定义 SQL 返回：

- 有效图书种类数与总册数。
- 有效读者数。
- 当前借出数与逾期数。
- 最近 30 天借阅次数最多的前五本图书。

### LEARNING-7：并发与审计

- 使用图书 `version` 乐观锁处理多人同时借最后一本书的场景。
- 冲突时最多重试一次，仍失败则返回 409。
- 增加管理员操作审计表，记录操作者、动作、业务类型、业务 ID、结果和时间。
- 编写并发测试证明库存不会成为负数，也不会产生超卖借阅记录。

## 6. 非功能要求

- Controller 只负责协议转换和校验，业务规则放在 Service，数据库访问放在 Mapper。
- 所有修改库存与借阅记录的操作必须有事务测试。
- 参数错误不暴露堆栈；未知异常统一返回通用错误信息并在服务端记录日志。
- 开发环境通过 Flyway 自动建表和初始化数据，禁止手工修改已执行的迁移文件。
- 新增接口必须同步更新 OpenAPI 注解和测试。

## 7. 第一阶段验收

- MySQL、后端和前端能够按 README 启动。
- `admin/admin123` 可以登录，错误密码无法登录。
- 未携带或携带无效 JWT 时，受保护接口返回 401。
- 图书页面能够读取初始化数据，支持关键词、分类、状态、分页与详情。
- 学习接口在未完成前稳定返回 HTTP 501，而不是导致项目启动失败。
- 后端测试、前端类型检查、ESLint 和生产构建通过。
